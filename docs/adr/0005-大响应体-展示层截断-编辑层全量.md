# ADR-0005 — 大响应体「展示层截断、编辑层全量」（B1 决策）+ stateVersion 轮询跳过

状态：已采纳 ｜ 日期：2026-10-24

## 背景

用户配置 MB 级 response body 后：接口管理视图打开即卡顿（卡片把完整 body 压平渲染进 DOM，浏览器需为全量文本节点排版，行数统计 `split('\n')` 还会生成几十万元素数组）；同时前端每 15s 全量轮询路由列表，每次都是 MB 级网络传输 + JSON.parse + 全部卡片重算，静置时周期性卡顿。

## 决策

1. **截断只允许出现在展示路径**（卡片折叠行预览 160 字符、`<pre>` 详情 2000 行 / 65536 字符先到为准并附总行数/字符数提示、WS 卡片剧本载荷 160 字符）。**编辑抽屉的 bodyText 始终加载完整内容，提交路径、curl/HTTP 响应、配置文件内容一律不截断**——保证"保存不丢数据"。截断实现见 `web/src/utils.ts` 的 `truncateForPreview`（统计用 indexOf 循环计数，不对 MB 级字符串 split 出大数组）。
2. **`GET /__polymock/meta` 返回 `stateVersion`**：注册表 `change` 时自增的内存态计数（不持久化，重启归零）。前端轮询先拉 meta，版本未变则跳过路由列表全量拉取（服务列表体积小仍每次拉取，WS 连接快照维持独立轮询）。显式刷新（编辑/删除/导入后的 loadAll）发生在变更之后，版本必然不同、不会被误跳过。

设计取舍：不用 HTTP ETag/304（需动缓存语义，对此体量过重）；不惰性加载路由明细（契约变化过大）。

## 后果

- 展示层 DOM 文本节点封顶，大 body 配置下打开与静置均无长任务；轮询只传 meta 小请求。
- 代价：卡片详情展示的是截断预览（提示行已注明"展开编辑可查看与修改完整内容"）；后端重启后 `stateVersion` 归零，若重启期间配置文件被外部改动且前端页面一直未做任何变更操作，路由列表需等下一次变更或手动刷新才更新（该边界已在方案评审中确认可接受）。
- 若未来要改"编辑抽屉也截断"（B2 场景），必须重新立项评审，不在本决策范围内。
