# ADR-0002 — WS 路由不升 SCHEMA_VERSION（老版本读到只是不命中）

状态：已采纳 ｜ 日期：2026-10-24

## 背景

WS 路由与 HTTP 路由共用 `polymock.config.json` 的 `routes` 数组（`protocol: "ws"`，`method` 固定 `WS`，行为配置收进 `ws` 子对象）。若为 WS 引入新的 schema 版本（升 `version`），旧版本 PolyMock 读到新配置文件时会走迁移逻辑甚至拒绝启动，混合使用新旧版本时配置文件互不兼容。

## 决策

WS 路由沿用 `version: 2`，**不升 `SCHEMA_VERSION`**。旧版本读入含 WS 路由的配置时：

- `method: "WS"` 不是任何 HTTP 方法，不参与 HTTP 分发——"只是不命中"，不产生错误响应；
- 加载与保存对路由对象按原文透传（registry 不做字段裁剪），WS 路由连同 `ws` 子对象在旧版本的读写循环中原样保留。

## 后果

- 配置文件在新旧版本之间双向兼容：旧版本可继续管理同一文件中的 HTTP 部分，不破坏 WS 配置。
- 代价：旧版本的控制台不展示 WS 卡片，WS 行为字段对其不可见（属预期）；不能利用 `version` 表达"该文件含新特性"，未来若有必须阻断旧版本读取的结构变更，需届时另立 ADR 升版本。
