# ADR-0004 — 帧级日志不持久化（500 条环形缓冲不被定时推送冲刷）

状态：已采纳 ｜ 日期：2026-10-24

## 背景

请求日志是容量 500 的环形缓冲（`RequestLogStore`，新到旧，内存态）。WS 连接的 interval 定时推送每 100ms-60s 产生一帧，若每帧都写一条日志，一个开启定时推送的接口即可在数秒内把 500 条缓冲全部冲刷，HTTP 请求日志与其他 WS 连接的关键事件都会被淹没。

## 决策

WS 日志**只写连接级、不写帧级**：连接建立与 close 时各记一条（`method: "WS"`，close 时记录 `ws.connectionId` / 收发帧计数 / `closeCode`）；帧内容只在 WS 调试台的帧时间线展示，仅保存在前端当前页面，不进入后端日志与持久化。

## 后果

- 环形缓冲不会被定时推送冲刷，日志对"发生了什么连接"保持可读。
- 代价：帧级流量无法事后审计（需要审计时应使用抓包工具或在被测端记录）；调试台刷新后帧历史清空（属预期，前端可按需复制关键帧）。
